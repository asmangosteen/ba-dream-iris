# Iris 기획 문서 양식 가이드

> 바드림 기획 · 디자인 · 개발 문서를 **Iris가 읽을 수 있는 모양**으로 쓰는 법이에요.
> 사람이 읽어도 되고, **AI(Claude · ChatGPT 등)에게 이 파일을 통째로 주고 일을 맡겨도** 돼요.
> 기준: Iris 문서 읽기 규칙 (2026-11-28)

---

## 0. 이 가이드는 무엇이고, 왜 이렇게 써야 하나요

### 무엇에 쓰나요

Iris는 문서를 올리면 그 안의 **요청사항(지켜야 할 규칙)** 과 **화면 목록**을 찾아, 캔버스의 실제 화면과 이어 줘요.
이어지고 나면 이런 게 저절로 돼요.

- 화면을 누르면 그 화면이 따라야 할 요청사항이 바로 보여요.
- 요청사항마다 화면에 반영됐는지(반영 · 일부 · 미반영 · 확인 전) 표시되고, 프로젝트 반영률이 나와요.
- 빠진 화면, 연결 안 된 요청사항, 겹친 번호를 경고로 알려 줘요.

### 왜 이 모양이어야 하나요

1. **Iris는 표와 ID로 읽어요.** 문장으로만 쓴 문서는 사람에겐 읽혀도 Iris는 어떤 게 규칙이고 어떤 게 화면인지 몰라요. 표 세 개만 정해진 모양이면 나머지는 자유예요.
2. **ID가 모두의 기준점이에요.** `P-PLN-01`, `C-05` 같은 번호 하나로 기획 · 디자인 · 개발 · QA가 같은 것을 가리켜요. 디자이너는 화면 이름에, 개발자는 API · 이슈에, QA는 버그 보고에 같은 번호를 써요.
3. **문서마다 모양이 다르면 연결이 조용히 깨져요.** 어떤 문서는 `M-05`, 어떤 문서는 `화면5`로 쓰면 Iris도 사람도 같은 화면인지 알 수 없어요.
4. **AI가 정리하기 쉬워요.** 규칙이 분명하니 이 가이드 하나만 주면 AI가 기존 문서를 같은 모양으로 바꿔 줄 수 있어요.

## 1. 이렇게 쓰세요 — AI와 함께

### A. 이미 있는 기획을 정리할 때 (가장 흔해요)

노션 · 워드 · 슬랙 메모 · 이전 기획서 등 이미 쓴 내용이 있다면:

1. 이 가이드 파일과 기존 문서(또는 내용 붙여 넣기)를 AI에게 함께 줘요.
2. 아래 부탁 문구를 그대로 붙여 넣어요.
3. 받은 `.md` 파일을 한 번 읽어 보고 Iris의 [Add document] → [Upload file] 로 올려요.

```
첨부한 'Iris 기획 문서 양식 가이드'의 「2. AI 작업 규칙」을 지켜서
이 문서를 Iris 양식으로 정리하고, Markdown(.md) 파일 하나로 저장해 줘.
문서 종류는 내용을 보고 네가 판단해서 문서 정보 표에 적어 줘.
```

### B. 처음부터 AI와 기획을 시작할 때

1. 대화 첫 메시지에 이 가이드 파일을 넣고 아래처럼 시작해요.
2. 대화하며 살을 붙이고, 마지막에 `.md` 로 저장해 달라고 해요.

```
이 'Iris 기획 문서 양식 가이드'대로 기획 문서를 함께 쓸 거야.
「2. AI 작업 규칙」을 지키고, 처음엔 문서 종류에 맞는 뼈대(5장)만 만든 다음
내가 말하는 내용을 요청사항 · 화면 표에 채워 가면서 정리해 줘.
만들려는 것: (한두 줄로 설명)
```

> 결과는 꼭 사람이 한 번 읽어요. `〔AI 추정〕` 이 붙은 곳은 특히요.

## 2. AI 작업 규칙

**AI는 이 장을 반드시 지켜요.** (사람이 직접 쓸 때도 같은 규칙이에요)

1. **문서 종류를 먼저 판단해** 문서 맨 위 「문서 정보」 표의 `문서 종류` 칸에 적는다. 3장 표의 이름 중 하나만 쓴다(서비스 기획서 · 정책서 · 디자인 요청서 · 개발 요청서 · 기타 문서). 섞여 있으면 가장 큰 목적 하나를 고른다.
2. 문서 정보 표 다음에 그 종류의 **뼈대(5장)** 순서로 장을 둔다. 원문에 있는데 뼈대에 없는 내용은 지우지 말고 알맞은 장 아래나 마지막 「부록」에 옮긴다.
3. **표 세 개(문서 정보 · 요청사항 · 화면)는 4장의 모양 그대로** 쓴다. 머리 줄 이름과 칸 순서를 바꾸지 않는다.
4. **ID 규칙(4장)을 지킨다.** 원문에 번호가 있으면 살리고, 옛 약자(`M` · `MA` · `MN` 등)는 새 약자로 바꾼다. 새로 붙인 번호 뒤에는 `〔AI 추정〕` 을 붙인다.
5. 화면 표의 **'요청사항' 칸은 비우지 않는다.** 원문으로 어떤 요청사항을 따르는지 판단이 서지 않으면 가장 가까운 것을 적고 `〔AI 추정〕`. 화면이 없는 규칙(서버 규칙 · 법무 고지 등)은 요청사항 이름 뒤에 `〔화면 없음〕`.
6. 정해지지 않은 것은 지어내지 않는다. 결정 대기는 `⏸`, 원문에 근거가 없는 빈칸은 비워 두고 문서 맨 끝 「확인 필요」 목록에 물어볼 것을 적는다.
7. 표 칸 안에서 줄을 바꿔야 하면 `<br>` 를 쓴다. 칸 안에 `|` 를 쓰려면 `\|`.
8. 결과는 **Markdown 파일 하나**로 준다. 파일 이름은 `문서 제목.md`.

## 3. 문서 종류

| 문서 종류 | 언제 쓰나요 | 꼭 넣는 표 | Iris 분류 |
|---|---|---|---|
| **서비스 기획서** | 기능 · 화면 단위 기획(화면 설계 · 스토리보드 포함) | 정보 · 요청사항 · 화면 | 기획 |
| **정책서** | 운영 · 비즈니스 규칙 모음(요금 · 환불 · 등급 · 약관 기준 등) | 정보 · 요청사항 (관련 화면이 있으면 화면 표도) | 기획 |
| **디자인 요청서** | 디자이너에게 화면 · 시안 작업을 맡길 때 | 정보 · 요청사항(디자인 요청 항목) · 대상 화면 | 디자인 |
| **개발 요청서** | 개발자에게 기능 구현을 맡길 때(기능 명세 · 개발 사양) | 정보 · 요청사항(기능 규칙) · 화면 | 개발 |
| **기타 문서** | 회의록 · 리서치 · 리포트 · 가이드 등 | 정보 | 기타 |

- Iris는 `문서 종류` 칸을 보고 **분류(기획 · 개발 · 디자인 · 기타)를 먼저 골라 둬요.** 올릴 때 바꿀 수 있어요.
- 기타 문서에도 `P-…` · `C-…` ID를 쓰면 링크로 바뀌어요.

## 4. 공통 규칙 — 표 세 개와 ID

### 4-1. 문서 정보 표 (모든 종류, 문서 맨 위)

| 항목 | 내용 |
|---|---|
| 문서 종류 | 디자인 요청서 |
| 문서 약어 | 구독 |
| 버전 | v1.0 |
| 상태 | 초안 |

- **문서 종류**: 3장 표의 이름 중 하나.
- **문서 약어**: 8자 이내. 한 프로젝트에 문서가 여럿이면 화면 ID 앞에 붙여 구분해요(예: `구독 C-05`).
- **상태**: `초안` · `검토` · `확정` 중 하나.
- 필요하면 행을 더해도 돼요(요청자 · 희망 완료일 · 하위 문서 등).
- 영어로도 읽어요: `Document type` · `Document abbreviation` · `Version` · `Status`(`Draft` · `Review` · `Confirmed`).

### 4-2. 요청사항 표

```
| ID | 요청사항 | 세부 규칙 |
| --- | --- | --- |
| P-PLN-01 | 요금제 구성 | 12 · 24 · 36개월, 기본 선택 24개월 |
```

- **ID는 `P-영역-번호`.** `P` 는 요청사항이라는 뜻으로 모든 문서 공통이에요.
  - **영역**: 영어 대문자 2~6자, 문서마다 자유(`PLN` 요금제 · `PAY` 결제 · `ORD` 주문 · `DSN` 디자인 요청 …). 쓰는 영역과 뜻을 문서 앞쪽에 한 줄로 적어 두세요.
  - **번호**: 숫자 1~4자리, `01` 처럼 두 자리 권장.
- 지운 번호는 다시 쓰지 않아요. 같은 ID가 두 번 나오면 경고가 떠요.
- 머리 줄은 `요청사항` · `정책` · `Request` · `Policy`, 세부 칸은 `세부 규칙` · `규칙` · `내용` · `설명` 모두 읽어요.
- 다른 문서의 요청사항을 근거로 하면 세부 칸에 그 ID를 적어요(예: 디자인 요청서의 `P-DSN-02` 세부 칸에 `기획 P-PLN-01 기준`).

### 4-3. 화면 표

```
| ID | 화면 | 보여 줄 것 | 상태 | 요청사항 |
| --- | --- | --- | --- | --- |
| C-01 | 요금제 선택 | 요금제 카드 3개 | 로딩, 오류 | P-PLN-01, P-PLN-02 |
```

- **'요청사항' 칸에 적은 ID가 그 화면에 '확인 전' 상태로 연결돼요.** 여러 개면 쉼표로.
  - 비어 있으면 '보여 줄 것' 문장 속 `P-…` 를 대신 읽고 경고로 알려 줘요.
- **'상태'** (로딩 · 빈 화면 · 오류 · 품절 등)는 그 화면의 상태 변형이 돼요. 없으면 `-`.
- **화면 ID 앞글자(종류 약자)는 모든 문서 공통**이에요.

| 약자 | 뜻 | 예시 |
|---|---|---|
| `C` | 고객 화면(앱 · 웹) | `C-05` |
| `A` | 관리자 화면(cydmin) | `A-01` |
| `S` | 센터 화면(케어샵 등) | `S-02` |
| `N` | 알림(푸시 · 문자 · 메일) | `N-03` |
| `CMP` | 공통 부품 | `CMP-01` |

- **캔버스 · 피그마 화면 이름도 같은 ID로** 지어요: `C-05 상품 상세`, 상태 변형은 `C-05/일시품절`. 이름이 ID로 시작하면 화면 칸에 저절로 붙어요.

### 4-4. 표기 기호

요청사항 이름이나 세부 칸 아무 데나 넣어요.

| 표기 | 뜻 | Iris에서 |
|---|---|---|
| `〔기본값〕` | 기획 권장안(확정 전) | 요청사항 옆 배지 |
| `⏸` | 결정 대기 | 연결된 화면에 '바뀔 수 있음' |
| `📌` | 개발 확인 | 개발 탭에 모아 보기 |
| `⚖️` | 법무 확인 | 요청사항 옆 배지 |
| `〔화면 없음〕` | 화면이 없는 규칙 | '화면 없음' 경고 · 반영률에서 빠져요 |
| `〔AI 추정〕` | AI가 붙인 번호 · 연결 | 사람이 확인하고 지워요 |

## 6. 경고와 고치는 법

올리면 **양식 검사**가 돌아요. 경고가 있어도 올릴 수 있고, 나중에 [Edit] 로 고치면 사라져요.

| 경고 | 고치는 법 |
|---|---|
| `C-02` 에 쓴 `P-PAY-09` 가 요청사항 표에 없어요 | 요청사항 표에 그 줄을 더하거나, 화면 표의 ID 오타를 고쳐요 |
| `C-03` 의 요청사항 칸이 비어 있어요 | 그 화면이 따르는 요청사항 ID를 적어요 |
| `P-PLN-04` 에 연결된 화면이 없어요 | 어떤 화면의 '요청사항' 칸에 넣거나, 화면이 없는 규칙이면 이름 뒤에 `〔화면 없음〕` |
| `C-01` 이 두 번 나와요 | 둘 중 하나에 새 번호를 줘요 |

## 7. Iris에 올리는 방법

[Add document] 에서 세 가지로 넣어요.

| 방법 | 어떻게 읽나요 |
|---|---|
| **Upload file** — Markdown(.md) | 표까지 바로 읽어요 **(권장 — AI가 준 .md 를 그대로)** |
| **Upload file** — PDF · Word | 파일로 보관만 해요. 요청사항 · 화면 연결이 필요하면 AI로 .md 로 바꿔 올려요 |
| **Paste link** — 공개 웹 페이지 | 글만 가져와요. 표는 글로만 남아 요청사항 · 화면은 연결되지 않아요. 로그인이 필요한 페이지(비공개 노션 · 구글 문서 · 컨플루언스)는 못 읽어요 |
| **Paste link** — .md 파일 주소 | GitHub raw · gist 같은 .md 주소는 표까지 읽어요 |
| **Write** — Iris에서 직접 | 문서 종류 틀을 골라 시작해요(5장 뼈대와 같아요) |

## 8. 전체 예시

### 서비스 기획서 예시

그대로 `.md` 로 저장해 올리면 요청사항 5개 · 화면 칸 4개 · 연결 6개가 잡혀요.

```markdown
# 착한구독 신청 기획서

## 문서 정보

| 항목 | 내용 |
| --- | --- |
| 문서 종류 | 서비스 기획서 |
| 문서 약어 | 구독 |
| 버전 | v1.0 |
| 상태 | 검토 |

영역 약자: PLN 요금제 · PAY 결제 · DOC 서류

## 배경 · 목표

전기이륜차 구독 신청을 앱에서 끝까지 할 수 있게 한다.

## 요청사항

| ID | 요청사항 | 세부 규칙 |
| --- | --- | --- |
| P-PLN-01 | 요금제 구성 | 12 · 24 · 36개월, 기본 선택 24개월 |
| P-PLN-02 | 가장 많이 선택 표시 | 24개월 카드에 배지 〔기본값〕 |
| P-DOC-01 | 서류 올리기 | 면허증 · 신분증 촬영 또는 앨범에서 올리기 📌 |
| P-DOC-02 | 심사 결과 알림 | 승인 · 반려 결과를 푸시로 알림 ⏸ |
| P-PAY-01 | 청약 철회 고지 | 결제 전 철회 가능 기간 안내 ⚖️ 〔화면 없음〕 |

## 화면

| ID | 화면 | 보여 줄 것 | 상태 | 요청사항 |
| --- | --- | --- | --- | --- |
| C-01 | 요금제 선택 | 요금제 카드 3개, 기본 24개월 선택 | 로딩, 오류 | P-PLN-01, P-PLN-02 |
| C-02 | 서류 제출 | 면허증 · 신분증 칸, 촬영 · 앨범 버튼 | 올리는 중, 실패 | P-DOC-01 |
| A-01 | 신청 심사(관리자) | 신청 목록 · 서류 보기 · 승인/반려 | 빈 화면 | P-DOC-01, P-PLN-01 |
| N-01 | 심사 결과 알림 | 승인 · 반려 푸시 문구 | - | P-DOC-02 |

## 결정 기록

- 2026-11-20 기본 선택을 24개월로 정함
```

### 디자인 요청서 예시

요청사항 3개 · 대상 화면 2개 · 연결 4개가 잡혀요.

```markdown
# 요금제 선택 화면 디자인 요청

## 문서 정보

| 항목 | 내용 |
| --- | --- |
| 문서 종류 | 디자인 요청서 |
| 문서 약어 | 구독 |
| 버전 | v1.0 |
| 상태 | 확정 |
| 요청자 | 기획팀 |
| 희망 완료일 | 2026-12-05 |

## 요청 배경 · 목표

요금제 선택 화면에서 이탈이 많다. 24개월 요금제를 고르기 쉽게 만들고 월 금액 비교를 한눈에 보이게 한다.

## 범위

- 포함: 요금제 선택(C-01), 요금제 비교 시트(C-03)
- 제외: 결제 화면, 관리자 화면

## 요청사항

| ID | 요청사항 | 세부 규칙 |
| --- | --- | --- |
| P-DSN-01 | 24개월 카드 강조 | '가장 많이 선택' 배지 + 카드 테두리 강조, 기획 P-PLN-02 기준 |
| P-DSN-02 | 월 금액 크게 | 월 금액을 가장 큰 글자로, 총액은 보조 글자 |
| P-DSN-03 | 디자인 시스템 사용 | 바드림 디자인 시스템 카드 · 버튼 · 배지만 사용 |

## 대상 화면

| ID | 화면 | 보여 줄 것 | 상태 | 요청사항 |
| --- | --- | --- | --- | --- |
| C-01 | 요금제 선택 | 요금제 카드 3개, 기본 24개월 선택 | 로딩, 오류 | P-DSN-01, P-DSN-02, P-DSN-03 |
| C-03 | 요금제 비교 시트 | 기간별 월 금액 · 총액 비교 표 | - | P-DSN-02 |

## 산출물 · 형식

- 피그마 프레임 이름: C-01 요금제 선택, 상태는 C-01/로딩 · C-01/오류
- 앱(390) 기준, 태블릿은 제외

## 일정 · 검토

- 1차 시안 12/02, 검토 기획팀 · 개발팀
```
