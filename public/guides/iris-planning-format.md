# Iris 기획서 양식 가이드

> 기획서를 이 양식대로 쓰면, Iris에 올리기만 해도 **요청사항 · 화면 · 둘 사이 연결**이 저절로 잡혀요.
> 새 양식을 외울 필요는 없어요. 지금 쓰는 기획서에 **표 세 개**만 이 모양으로 넣으면 돼요.

- 대상: 바드림 기획 · 디자인 · 개발
- 기준: Iris 문서 읽기 규칙(2026-11-28)
- 이 파일을 AI(Claude · ChatGPT 등)에게 주고 "이 양식대로 바꿔 줘"라고 해도 돼요. 맨 아래 [AI에게 맡길 때](#8-ai에게-맡길-때)를 보세요.

---

## 1. 한눈에 보기

| 꼭 넣을 것 | 무엇이 되나요 |
|---|---|
| ① 문서 정보 표 | 문서 이름 옆 약어 · 버전 · 상태 칩 |
| ② 요청사항 표 | 요청사항 목록(요청사항 보기 · 반영률) |
| ③ 화면 표 | 화면 칸 — 캔버스 화면과 이어지는 자리. '요청사항' 열의 ID가 그 화면에 연결돼요 |

나머지(배경 · 플로우 · 상태 정의 · 알림 문구 · 결정 기록 · 부록 등)는 **자유롭게** 쓰세요. Iris는 그 안의 ID를 찾아 링크로만 바꿔 줘요.

---

## 2. ① 문서 정보 표

두 칸짜리 표예요. 앞 칸 이름이 아래와 같으면 읽어요.

| 항목 | 내용 |
|---|---|
| 문서 | 착한구독 상세 기획서 |
| 문서 약어 | 구독 |
| 버전 | v1.0 |
| 상태 | 초안 |

- **문서 약어**: 8자 이내. 한 프로젝트에 기획서가 여럿이면 화면 ID 앞에 붙여 구분해요(예: `구독 C-05`).
- **상태**: `초안` · `검토` · `확정` 중 하나.
- 영어로 써도 돼요: `Document abbreviation` · `Version` · `Status`(`Draft` · `Review` · `Confirmed`).

## 3. ② 요청사항 표

```
| ID | 요청사항 | 세부 규칙 |
| --- | --- | --- |
| P-PLN-01 | 요금제 구성 | 12 · 24 · 36개월 세 가지, 기본 선택은 24개월 |
| P-PLN-02 | 가장 많이 선택 표시 | 24개월 카드 위에 '가장 많이 선택' 배지 〔기본값〕 |
| P-PAY-01 | 청약 철회 고지 | 결제 전 철회 가능 기간 안내 ⚖️ 〔화면 없음〕 |
```

- **ID 모양은 `P-영역-번호`** 예요.
  - `P` 는 요청사항이라는 뜻(모든 문서 공통, 바꾸지 않아요).
  - **영역**은 영어 대문자 2~6자로 문서마다 자유롭게 정해요(`PLN` 요금제, `PAY` 결제, `ORD` 주문 …). 영역 약자와 뜻은 문서 앞쪽에 따로 적어 두면 좋아요.
  - **번호**는 숫자 1~4자리. `01` 처럼 두 자리로 맞추길 권해요.
- 머리 줄 이름은 `요청사항` · `정책` · `Request` · `Policy` 모두 읽어요. 세부 칸은 `세부 규칙` · `규칙` · `내용` · `설명` 중 하나면 돼요.
- **지운 번호는 다시 쓰지 마세요.** 같은 ID가 두 번 나오면 경고가 떠요.
- 표 밖에서 `- P-PLN-03 해지 위약금 안내 …` 처럼 **줄 맨 앞에 ID** 를 쓴 목록도 요청사항으로 읽어요. 그래도 표로 모아 두는 쪽이 보기 좋아요.

## 4. ③ 화면 표

```
| ID | 화면 | 보여 줄 것 | 상태 | 요청사항 |
| --- | --- | --- | --- | --- |
| C-01 | 요금제 선택 | 요금제 카드 3개, 기본 24개월 선택 | 로딩, 오류 | P-PLN-01, P-PLN-02 |
| C-02 | 결제 확인 | 결제 금액 · 철회 안내 · 결제 버튼 | - | P-PAY-01 |
| A-01 | 구독 신청 목록(관리자) | 신청 목록 · 상태 필터 | 빈 화면 | P-PLN-01 |
```

- **'요청사항' 열이 가장 중요해요.** 이 칸에 적은 ID가 그 화면에 '확인 전' 상태로 연결돼요. 여러 개면 쉼표로 이어 쓰세요.
  - 이 칸이 비어 있으면 '보여 줄 것' 문장 속 `P-…` 를 대신 읽고, 경고로 알려 줘요.
- **'상태'** 열(로딩 · 빈 화면 · 오류 · 품절 등)은 그 화면의 상태 변형이 돼요. 없으면 `-`.
- **화면 ID 앞글자(종류 약자)는 모든 문서 공통**이에요. Iris는 이 약자로 화면인지 판단해요.

| 약자 | 뜻 | 예시 |
|---|---|---|
| `C` | 고객 화면(앱 · 웹) | `C-05` |
| `A` | 관리자 화면(cydmin) | `A-01` |
| `S` | 센터 화면(케어샵 등) | `S-02` |
| `N` | 알림(푸시 · 문자 · 메일) | `N-03` |
| `CMP` | 공통 부품 | `CMP-01` |

- 옛 약자(`M` · `MA` · `MN` 등)를 쓰던 문서는 위 약자로 바꿔 주세요.
- 머리 줄 이름: 화면 칸은 `화면` · `Screen`, 내용은 `보여 줄 것` · `구성` · `내용`, 상태는 `상태` · `State`, 연결은 `요청사항` · `정책` · `Request` 를 읽어요.

### 캔버스 화면 이름도 같은 ID로

캔버스(또는 피그마)에서 화면 이름을 **`C-05 상품 상세`** 처럼 ID로 시작하면 그 화면 칸에 저절로 붙어요.
상태 변형은 **`C-05/일시품절`** 처럼 `/` 뒤에 적어요.

## 5. 표기 기호

기존 기획서에서 쓰던 기호를 그대로 알아봐요. 요청사항 이름이나 세부 규칙 칸 아무 데나 넣으면 돼요.

| 표기 | 뜻 | Iris에서 |
|---|---|---|
| `〔기본값〕` | 기획 권장안(확정 전) | 요청사항 옆 배지 |
| `⏸` | 결정 대기 | 연결된 화면에 '바뀔 수 있음' |
| `📌` | 개발 확인 | 개발 탭에 모아 보기 |
| `⚖️` | 법무 확인 | 요청사항 옆 배지 |
| `〔화면 없음〕` | 화면이 없는 규칙(서버 규칙 · 법무 고지 등) | '화면 없음' 경고와 반영률에서 빠져요 |

## 6. 경고와 고치는 법

문서를 올리면 **양식 검사**가 돌아요. 경고가 있어도 올릴 수 있고, 나중에 [Edit] 로 고치면 사라져요.

| 경고 | 고치는 법 |
|---|---|
| `C-02` 에 쓴 `P-PAY-09` 가 요청사항 표에 없어요 | 요청사항 표에 그 줄을 더하거나, 화면 표의 ID 오타를 고쳐요 |
| `C-03` 의 요청사항 칸이 비어 있어요 | 그 화면이 따르는 요청사항 ID를 '요청사항' 열에 적어요 |
| `P-PLN-04` 에 연결된 화면이 없어요 | 어떤 화면의 '요청사항' 열에 넣거나, 화면이 없는 규칙이면 이름 뒤에 `〔화면 없음〕` |
| `C-01` 이 두 번 나와요 | 둘 중 하나에 새 번호를 줘요 |

## 7. 올리는 방법

[Add document] 에서 세 가지로 넣을 수 있어요.

| 방법 | 읽기 |
|---|---|
| **Write**(Iris에서 직접 쓰기) | 바로 읽어요. 'Spec' 틀을 고르면 이 양식의 뼈대가 들어가요 |
| **Upload file** — Markdown(.md) | 바로 읽어요 **(권장)** |
| **Upload file** — PDF · Word | 파일로 보관만 해요. 요청사항 · 화면 연결이 필요하면 Markdown으로 바꿔 올리거나, 문서를 열어 내용을 붙여 넣으세요 |
| **Paste link** | 페이지 글을 가져와 읽어요. 못 가져오면 링크만 남기고 내용을 붙여 넣을 수 있어요 |

Markdown 쓰는 법은 간단해요: `# 제목`, `## 소제목`, `- 목록`, 빈 줄로 문단 나누기, 표는 `| 칸 | 칸 |` 줄 아래 `| --- | --- |`.

## 8. AI에게 맡길 때

이미 써 둔 기획서가 있다면, 이 가이드 파일과 기획서를 함께 AI에게 주고 아래처럼 부탁하세요.

```
첨부한 'Iris 기획서 양식 가이드'대로 이 기획서를 Markdown으로 바꿔 줘.
- 문서 정보 표 · 요청사항 표 · 화면 표 세 개를 꼭 넣고, 나머지 내용은 그대로 둬.
- 요청사항 ID는 P-영역-번호(영역은 영어 대문자 2~6자), 화면 ID는 C · A · S · N · CMP-번호로.
- 문서에 이미 번호가 있으면 그 번호를 살리고, 새로 붙인 번호나 추측한 연결은 끝에 〔AI 추정〕을 붙여 줘.
- 화면 표의 '요청사항' 열은 비우지 마. 화면이 없는 규칙은 이름 뒤에 〔화면 없음〕.
- 결과는 .md 파일 하나로.
```

받은 결과는 꼭 한 번 읽어 보고 올리세요. 〔AI 추정〕 표시가 붙은 곳은 특히요.

## 9. 전체 예시

아래를 그대로 복사해 `.md` 파일로 저장하고 올리면, 요청사항 5개 · 화면 칸 4개 · 연결 6개가 잡혀요.

```markdown
# 착한구독 신청 기획서

## 1. 문서 정보

| 항목 | 내용 |
| --- | --- |
| 문서 | 착한구독 신청 기획서 |
| 문서 약어 | 구독 |
| 버전 | v1.0 |
| 상태 | 검토 |

영역 약자: PLN 요금제 · PAY 결제 · DOC 서류

## 2. 배경

전기이륜차 구독 신청을 앱에서 끝까지 할 수 있게 한다. (자유롭게 쓰는 장)

## 3. 요청사항

| ID | 요청사항 | 세부 규칙 |
| --- | --- | --- |
| P-PLN-01 | 요금제 구성 | 12 · 24 · 36개월, 기본 선택 24개월 |
| P-PLN-02 | 가장 많이 선택 표시 | 24개월 카드에 배지 〔기본값〕 |
| P-DOC-01 | 서류 올리기 | 면허증 · 신분증 촬영 또는 앨범에서 올리기 📌 |
| P-DOC-02 | 심사 결과 알림 | 승인 · 반려 결과를 푸시로 알림 ⏸ |
| P-PAY-01 | 청약 철회 고지 | 결제 전 철회 가능 기간 안내 ⚖️ 〔화면 없음〕 |

## 4. 화면

| ID | 화면 | 보여 줄 것 | 상태 | 요청사항 |
| --- | --- | --- | --- | --- |
| C-01 | 요금제 선택 | 요금제 카드 3개, 기본 24개월 선택 | 로딩, 오류 | P-PLN-01, P-PLN-02 |
| C-02 | 서류 제출 | 면허증 · 신분증 칸, 촬영 · 앨범 버튼 | 올리는 중, 실패 | P-DOC-01 |
| A-01 | 신청 심사(관리자) | 신청 목록 · 서류 보기 · 승인/반려 | 빈 화면 | P-DOC-01, P-PLN-01 |
| N-01 | 심사 결과 알림 | 승인 · 반려 푸시 문구 | - | P-DOC-02 |

## 5. 결정 기록

- 2026-11-20 기본 선택을 24개월로 정함 (자유롭게 쓰는 장)
```
