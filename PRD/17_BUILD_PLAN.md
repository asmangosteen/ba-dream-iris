## 3. 단계별 내용

### 1. 함께 쓰기 바탕(2-D)

- **DB**: `project_members`(역할 6가지), `project_invites`(대기 · 승인 · 거절 · 만료, 7일), `notifications`, `activity_log`. 역할을 보는 DB 보안 규칙(`project_role()`), 기존 프로젝트 이관(만든 사람 = 방장, 나머지 = 직무에 맞는 편집 역할).
- **화면**: A 멤버 · 초대 창, B 초대받은 사람 첫 화면 · 멤버가 아닐 때 화면, 10 프로젝트 설정 탭(일반 · 멤버 · 문서 규칙 · 위험), 11 Share → A, 12 알림 종 + G 알림 목록, 14 보기 전용 모드, 15 오류 문구, 9 홈(내 프로젝트 · 역할 · '승인 대기 초대' 배지).
- **링크 공유**: 사내 계정(`@ba-dream.com`)만. 링크를 받은 사람이 멤버가 아니면 B 화면에서 [참여 요청] → 승인 흐름.
- **초대 메일**: 아래 5장 결정 4.

### 2. 실시간 · 코멘트

- **함께 보는 중(J)**: 프로젝트 · 페이지마다 실시간 채널(Supabase Realtime presence). 상단 아바타, 화면 라벨 옆 "박디자님도 보고 있어요".
- **다중 커서**: 같은 페이지 사람들의 마우스 위치 · 이름표, 고른 레이어 테두리(이름 색). 위치는 0.05초마다만 보내 부담을 줄인다.
- **저장 충돌(J)**: 저장할 때 서버 쪽이 내가 연 뒤 바뀌었으면 덮어쓰지 않고 [다른 사람 것 보기] · [내 것으로 저장]. 다른 사람이 저장하면 내 화면에 바로 반영(내가 고치는 중이 아닐 때).
- **코멘트**(피그마와 같은 방식): 코멘트 도구(C), 캔버스 · 화면 위 핀, 스레드 · 답글, @멘션 → 알림, 해결 · 다시 열기, 오른쪽 코멘트 목록, 보기 전용도 코멘트 가능(12장 표).
- **실시간 동시 편집**(같은 화면을 둘이 동시에 고치고 서로 바로 보기)은 이 단계에서 하지 않는다〔제안〕. 커서 · 충돌 묻기로 먼저 쓰고, 필요하면 Phase 3에서 동시 편집 방식(CRDT)으로 바꾼다. 아래 5장 결정 7.

### 3. 기획서 양식 읽기(2-A)

- 인식 규칙: 표 칸 안 `P-영역-숫자` · 화면 ID(C · A · S · N · CMP), `REQ-nnn` 자동 부여 없애기.
- 문서 블록에 표 더하기, 화면 표 → 화면 칸(ScreenSlot), '정책' 열 → '확인 전' 연결, 양식 검사 · 경고.
- DB: `requirements`에 영역 · 표기 · 화면 유무 · 빠진 날 열, 문서마다 같은 ID 허용(유일 조건 바꾸기), `screen_slots`.
- 화면: 1 문서 추가 창 · 2 문서 상세(검사 막대 · ID 강조 · 표기 배지) · 3 Docs 탭 · 7 개발 탭 · 13 명령 팔레트 ID 검색 · 16 문구 · K 문서 규칙.

### 4. 피그마 ↔ 화면 칸 + 실제 연동(2-B)

- **토큰**: 팀 공용 피그마 계정 토큰을 서버에 보관(지금처럼 환경 변수 → `figma_connections`에 암호화). 만료 7일 전 관리자 알림.
- **가져오기**: 페이지 · 섹션 링크, 미리보기 표(4), 진행률, 호출 한도(429) 뒤 이어 받기, 프레임 이름 ID → 화면 칸(I), 상태 변형 · 대표 시안.
- **바뀜 감지**: 다시 불러오기 · 하루 한 번 자동 확인, 썸네일 기록, ID 바뀜 확인, 원본 없음 표시.
- **피그마 스타일 · 변수 → Iris 토큰**: 색 · 글자 · 효과 스타일은 피그마 공개 API로 가져올 수 있다. **피그마 변수(Variables) API는 Enterprise 플랜에서만 열린다** — 아니라면 피그마 플러그인으로 내보내기(Phase 3) 또는 디자인 시스템 코드 토큰을 그대로 쓴다. 5장 결정 5.
- **편집 가능한 레이어로 가져오기**: 지금은 썸네일만. 피그마 노드(프레임 · 오토 레이아웃 · 글자 · 칠 · 효과 · 벡터 · 인스턴스)를 Iris 레이어로 바꾸면 피그마 화면을 Iris에서 바로 고칠 수 있다. 크고(3~5일 더) Phase 3 계획이었다. 5장 결정 6.
- 화면: 5 캔버스 라벨(ID · 단계 · 재검토 · 연결 안 됨 · 원본 없음), 6 기획 탭 화면 칸 줄, 8 정책 보드 '빠진 것'.

### 5. 검수 흐름(2-C)

- 반영 상태 6가지 · 새 반영률, 문서 버전 · 확정 · 비교(C) · 변경 요약 복사, 재검토 창(E), 검토 요청 · 승인 · 반려(F) · 담당 디자이너, 기록(H), 홈 반영률 · '재검토 n'.
- DB: 문서 · 정책 버전, 화면 스냅샷(썸네일 기록 · 화면 버전 기록 겸용), 반영 상태 두 가지 추가.

### 6. 편집 5묶음

- PNG · SVG 내보내기(1x · 2x · 3x, 화면 · 레이어), 픽셀 미리보기(내보내기와 같은 그림 만들기를 씀).
- 레이어 검색 · 이름 일괄 바꾸기, 프로토타입 연결(화면 → 화면, 누르기 · 뒤로) · 미리보기 창.
- 화면 버전 기록은 5단계의 화면 스냅샷을 그대로 쓴다.

### 7. 양식 변환 AI(2-E)

- 장 단위 변환 작업(뒤에서) · 진행률 · 끝나면 알림, 비교 화면(D, C와 같은 틀), 〔AI 추정〕 받기 · 고치기 · 빼기.
- 서버에 AI 키가 필요하고 쓸 때마다 비용이 든다. 5장 결정 8.
