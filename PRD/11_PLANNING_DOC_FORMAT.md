# Iris 기획서 양식 · ID 규칙

> 2026-11-26 확정. 바드림 몰 상세 기획서 v1.0 · 대차 · 단기구독 통합 서비스 기획서 v6.0을 보고 정했다.
> 목표: **기획서를 올리기만 하면 정책 · 화면 · 둘 사이 연결이 저절로 잡히는 것.**
>
> **팀에 배포하는 최종 양식 가이드는 [`public/guides/iris-planning-format.md`](../public/guides/iris-planning-format.md)** 다(2026-11-28). 서비스의 [Add document] 창에서 내려받는다. 이 문서는 결정 기록이고, 화면 이름은 그 뒤 '정책' → **'요청사항'** 으로 바뀌었다(표 머리는 둘 다 읽음).

## 1. 기본 방향

- 새 양식을 만들지 않는다. 바드림 기획서가 이미 쓰는 뼈대(문서 정보 → 정책 일람 → 플로우 → 상태 → 화면 구성 → 알림 → 결정 로그)를 그대로 쓰고, Iris가 읽는 데 필요한 것만 **필수**로 정한다.
- Iris는 번호를 새로 만들지 않는다. **문서 안 ID를 그대로** 정책 · 화면의 번호로 쓴다(지금의 `REQ-nnn` 자동 부여는 없앤다).

## 2. 필수 세 가지

### 2-1. 문서 정보 표

| 항목 | 예시 |
|---|---|
| 문서 | 바드림 몰 상세 기획서 |
| 문서 약어 | 몰 |
| 버전 | v1.0 |
| 상태 | 초안 / 검토 / 확정 |
| 하위 문서 | 디자인 요청서 v1.0, 개발 사양서 v1.0 |

### 2-2. 정책 표 — Iris의 "요구사항" 단위

```
| ID | 정책 | 세부 규칙 |
| P-ORD-05 | 배송지 확인 | 결제 전에 배송지 확인 창을 띄운다 … |
```

- ID는 `P-영역-연번`. 지운 번호는 다시 쓰지 않는다.

### 2-3. 화면 표 — Iris의 화면 칸

```
| ID | 화면 | 보여 줄 것 | 상태 | 정책 |
| C-12 | 배송지 확인 창 | 받는 분 · 주소 · 요청사항 … | - | P-ORD-05 |
```

- **'정책' 열이 필수**다. 이 열의 ID가 그 화면에 연결된다.
- 열이 비어 있으면 '보여 줄 것' 문장 속 `(P-…)`를 읽는 것으로 대신한다.
- '상태' 열(로딩 · 빈 화면 · 오류 · 품절 등)은 그 화면의 상태 변형이 된다.

나머지 장(플로우 · 상태 정의 · 알림 · 법무 · 결정 로그 · 부록)은 자유롭게 쓴다. Iris는 그 안의 ID를 링크로만 바꿔 준다.

## 3. ID 규칙

### 3-1. 종류 약자 — 모든 문서 공통으로 고정

Iris는 이 약자로 정책인지 화면인지 판단한다.

| 약자 | 뜻 | 예시 |
|---|---|---|
| **P** | 정책 | `P-ORD-03` |
| **C** | 고객 화면(앱 · 웹) | `C-05` |
| **A** | 관리자 화면(cydmin) | `A-01` |
| **S** | 센터 화면(케어샵 등) | `S-02` |
| **N** | 알림 | `N-05` |
| **CMP** | 공통 부품 | `CMP-03` |

### 3-2. 영역 약자 — 문서마다 자유

- `P-` 뒤의 영역(`PRD` 상품, `ORD` 주문, `STR` 단기구독 …)은 서비스마다 달라서 미리 정하지 않는다.
- 문서의 표기 규칙 표에 영역 약자와 뜻을 적는다.

### 3-3. 겹침 · 옛 약자

- 한 프로젝트에 기획서가 여럿이면 화면 ID가 겹칠 수 있다(두 문서 모두 `C-05`). 프로젝트 안에서는 **문서 약자와 함께** 보여 준다(예: `몰 C-05`).
- 기존 문서의 옛 약자(바드림 몰의 `M` · `MA` · `MN`)는 양식 변환으로 바꾸거나, 프로젝트 설정에서 새 약자에 대응시켜 읽는다(예: `M` = `C`, `MA` = `A`, `MN` = `N`).
- 번호 없이 직접 지정한 문장은 임시 번호(`#12`)를 붙여 문서에 없는 번호임을 드러낸다. 양식 변환 때 `P-…` 번호로 문서에 적는다.

## 4. 표기 표시

기존 기획서 표기를 그대로 인식한다.

| 표기 | 뜻 | Iris에서 |
|---|---|---|
| ✅ | 확정 결정 | 표시 없음 |
| 〔기본값〕 | 기획 권장안 | 정책 옆 작은 배지 |
| ⏸ | 결정 대기 | 연결된 화면에 "바뀔 수 있음" |
| 📌 개발 확인 | 개발이 놓치기 쉬운 규칙 | 인스펙터 개발 탭에 모음 |
| ⚖️ 법무 확인 | 법무 원문 확인 필요 | 정책 옆 배지 |

## 5. 자동으로 되는 것

- 화면 표의 행마다 화면 칸이 생기고, '정책' 열의 정책이 연결 후보로 붙는다.
- 피그마 프레임 이름을 `C-05 상품 상세`, `C-05/일시품절`처럼 지으면 화면 칸에 저절로 붙는다.
- 새 버전을 올리면 ID 기준으로 추가 · 수정 · 삭제를 비교해 **변경 요약을 자동으로** 만든다. 바뀐 정책에 연결된 화면은 '재검토 필요'가 된다. 문서 안에 🆕 · 🔄 표시나 '대체 문장' 표를 따로 쓸 필요가 없다.

## 6. 문서를 올리는 두 길

1. **양식대로 쓴 문서**: 바로 읽어서 정책 · 화면 · 연결을 만든다.
2. **자유롭게 쓴 문서**: AI가 양식으로 바꾼 초안을 만들고, 사람이 확인 · 확정하면 등록한다.
   - 원본은 그대로 두고, 바꾼 문서는 새 버전으로 저장한다.
   - AI가 새로 붙인 ID나 추측한 연결은 〔AI 추정〕으로 표시한다.
   - 화면 표를 만들 근거가 없으면 비워 두고 "화면 목록이 없어요"라고 알린다.
   - 긴 문서는 장 단위로 나눠 바꾼다(비용 · 시간).
   - Phase 2 'AI 요구사항 초안'을 이 기능으로 넓힌다.

- 인식 규칙: 지금은 줄 맨 앞의 `REQ|FR|NFR|SR-숫자`만 읽는다(`app/composables/useIrisData.ts`, `app/components/docs/DocEditor.vue`). → 표 칸 안의 `P-영역-숫자`와 종류 약자별 화면 ID를 읽도록 바꾼다.
