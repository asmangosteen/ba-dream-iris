### 2. 문서 상세 — `pages/p/[projectId]/docs/[docId].vue`, `DocReader.vue`, `DocEditor.vue`

- **머리 줄**: 문서 상태(초안 · 검토 · 확정) 칩, 버전 고르기(v1.0 ▾), [확정] · [새 버전 만들기]. 확정된 문서는 [편집] 대신 [새 버전 만들기]만 보인다.

## 2. 새로 만들 화면

모든 창은 프로필 편집 창 양식(`main.css`의 `.pop-*`)을 따르고, 확인은 공용 `AppConfirm`을 쓴다.

### A. 멤버 · 초대 창

Share 버튼과 프로젝트 설정 '멤버' 탭에서 같은 내용을 쓴다.

```
┌ 멤버 · 초대 ─────────────────────────── ✕ ┐
│ [이메일 입력                 ] [초대 요청]  │  ← 방장·부방장은 [초대] + 역할 고르기
│                                           │
│ 승인 대기 2                    (방장·부방장만) │
│  kim@…  요청: 박디자  [역할 ▾] [승인] [거절] │
│                                           │
│ 멤버 6                                     │
│  이기획  방장                               │
│  박디자  디자인 편집 ▾   …(내보내기)          │
│                                           │
│ 내가 보낸 요청 1 · 대기 중 (6일 남음)          │
│                          [링크 복사]        │
└───────────────────────────────────────────┘
```

- 역할 드롭다운은 방장 · 부방장에게만 열린다. 부방장 임명 · 해제는 방장만.
- 승인 버튼은 역할을 고르기 전에는 꺼져 있다.
- 빈 상태: "아직 혼자예요. 함께할 사람을 초대해 보세요".

### B. 초대받은 사람 첫 화면 · 멤버가 아닐 때 화면

- 초대 메일 → 로그인 → "**착한구독 개편**에 **디자인 편집**으로 초대됐어요" + [들어가기].
- 만료 · 취소된 초대: "초대가 만료됐어요" + [참여 요청].
- 멤버가 아닌 프로젝트 링크로 들어옴: "이 프로젝트의 멤버가 아니에요" + [참여 요청]. 참여 요청은 초대 요청과 같은 승인 흐름을 탄다〔기본값〕.

### C. 버전 비교 · 변경 요약 화면

새 버전을 올리거나 [확정]을 누를 때 연다. [14_REVIEW_FLOW.md](./14_REVIEW_FLOW.md) 3장.

```
┌ v1.0 → v1.1 비교 ───────────────────────────────────────┐
│ 왼쪽 목록                    │ 오른쪽                     │
│ 수정 3   P-ORD-05 …          │ P-ORD-05 배송지 확인         │
│ 추가 2   P-ORD-21 …          │ 전: 결제 전에 … (지운 글자 빨강) │
│ 삭제 1   P-DLV-07 …          │ 후: 결제 직전에 … (더한 글자 초록)│
│ 표기 1   P-SUP-03 ⏸→✅       │ 영향 화면: C-11 · C-12        │
│ 화면 +1  C-23                │                            │
├─────────────────────────────┴────────────────────────────┤
│ 확정하면 화면 4개가 '재검토 필요'가 돼요  [변경 요약 복사] [확정] │
└───────────────────────────────────────────────────────────┘
```

- [변경 요약 복사]는 바드림 기획서의 '변경 요약' 표 모양 그대로 복사한다.
- 양식 변환 비교 화면(D)과 틀을 함께 쓴다.

### D. 양식 변환 비교 화면

[15_DOC_CONVERT.md](./15_DOC_CONVERT.md) 4장.

- 왼쪽 원본 · 오른쪽 변환본, 장 단위로 함께 스크롤.
- 〔AI 추정〕 항목 강조, 항목마다 [받기] · [고치기] · [빼기], 위에 [모두 받기].
- **변환 중 상태**: 장 단위 진행률(5 / 13장), "다 되면 알려 드려요. 창을 닫아도 돼요".
- **실패 상태**: 실패한 장만 [다시 시도].
- 다 고르면 [확정] → 새 버전(초안)으로 저장.

### E. 재검토 창

'재검토 필요' 정책의 [전 · 후 보기]에서 연다.

- 바뀐 이유에 따라 두 가지를 나란히 보여 준다.
  - 디자인이 바뀜: 직전 썸네일 ↔ 지금 썸네일(최근 5개 중 고르기).
  - 정책이 바뀜: 전 문장 ↔ 후 문장(바뀐 글자 강조).
- 아래에서 바로 반영 상태를 다시 고른다(반영됨 · 일부 · 미반영 · 해당없음) → 다음 '재검토 필요'로 넘어가기.

### F. 검토 요청 · 승인 · 반려 창

- 검토 요청: 남은 '확인 전' · '미반영' · '재검토 필요' 개수를 보여 주고 [요청 보내기].
- 승인: 남은 것이 있으면 **사유 메모를 적어야** 승인 버튼이 켜진다.
- 반려: 사유 필수. 담당 디자이너에게 알림.

### G. 알림 목록

상단 종에서 여는 패널.

- 줄마다: 아이콘 · 한 줄 내용 · 프로젝트 이름 · 시간. 안 읽은 줄은 점.
- 묶음 알림: "새 버전 v1.1 확정 · 내 화면 4개 재검토 필요"처럼 한 줄.
- 누르면 대상(화면 · 문서 · 초대)으로 이동하고 읽음 처리. 위에 [모두 읽음].
- 빈 상태: "새 알림이 없어요".

### H. 기록 목록

기획 탭 [모두 보기], 정책 상세, 프로젝트 설정 '멤버' 탭에서 연다.

- 줄마다: 누가 · 무엇을 · 전 → 후 · 언제. 고치거나 지우는 버튼은 없다.
- 거르기: 사람 · 종류(반영 상태 · 승인 · 역할 · 문서).

### I. 화면 칸 고르기 · ID 바뀜 확인

- **화면 칸 고르기**: 기획 탭 [화면 칸 고르기] → 검색 팝오버(ID · 이름), 상태 변형이면 상태도 고르기, 디자인이 이미 있는 칸은 "대표 시안으로 둘까요?"를 묻는다.
- **ID 바뀜 확인**: 피그마 다시 불러오기에서 프레임 이름의 ID가 바뀌면 "C-05에서 C-06으로 바뀌었어요. 화면 칸도 옮길까요?" (AppConfirm).

### J. 함께 보는 중 표시 · 저장 충돌 창

[14_REVIEW_FLOW.md](./14_REVIEW_FLOW.md) 7장.

- 화면 라벨 옆 작은 아바타 + "박디자님도 보고 있어요".
- 저장 충돌 창: "다른 사람이 먼저 저장했어요" + [다른 사람 것 보기] · [내 것으로 저장].

### K. 프로젝트 설정 '문서 규칙' 칸

- **옛 약자 대응**: `M` → `C`, `MA` → `A`, `MN` → `N` 줄을 더하고 뺀다.
- **영역 약자 목록**: 문서들에서 읽은 영역 약자(PRD · ORD …)와 뜻을 보기만 한다.
