# 검수 흐름 · 변경 추적 · 알림

> 2026-11-26 작성. 기획서([11](./11_PLANNING_DOC_FORMAT.md)) · 피그마 연동([13](./13_FIGMA_LINK.md)) · 역할([12](./12_ROLES_PERMISSIONS.md))이 만나는 곳이다.
> 목표: **기획이 바뀌거나 디자인이 바뀌면, 다시 봐야 할 화면이 저절로 드러나는 것.** Iris의 핵심 가치(누락 · 불일치 검수)와 바로 이어진다.
> 〔기본값〕은 기획 권장안이다. 답이 없으면 이대로 만든다.

## 1. 단계

### 1-1. 문서

```
초안 → 검토 → 확정 ─(고칠 때)→ 새 버전 초안 → … → 확정
```

- 기획서 문서 정보 표의 '상태'와 같은 값이다.
- **확정**은 방장 · 부방장 · 기획 편집이 한다.
- 확정된 문서는 바로 고치지 못한다. '새 버전 만들기'로 고치고, 새 버전을 확정할 때 2장의 변경 추적이 돈다.

### 1-2. 화면

```
작업 중 → 검토 요청 → 승인
              ↑          │ 디자인이 바뀌거나 연결된 정책이 바뀌면
              └──────────┘
```

- **검토 요청**은 화면을 편집할 수 있는 사람이 보낸다. 방장 · 부방장에게 알림이 간다.
- **승인**은 방장 · 부방장이 한다.
- 승인 조건〔기본값〕: 그 화면에 '확인 전' · '미반영' · '재검토 필요' 연결이 하나도 없을 때만 승인 버튼이 켜진다. 그래도 승인하려면 사유 메모를 꼭 남긴다.
- 반려하면 사유와 함께 담당 디자이너에게 알린다.

## 2. 반영 상태

| 상태 | 색 | 뜻 | 누가 바꾸나 |
|---|---|---|---|
| 확인 전 | 연회색 테두리 | 자동으로 연결만 되고 아직 아무도 안 봄 | Iris가 붙임 |
| 반영됨 | 초록 | 화면이 정책대로 됨 | 사람 |
| 일부 반영 | 주황 | 일부만 됨(메모 필수〔기본값〕) | 사람 |
| 미반영 | 빨강 | 빠짐 | 사람 |
| 해당없음 | 연회색 | 이 화면과 상관없음 | 사람 |
| 재검토 필요 | 보라〔기본값〕 | 정책이나 디자인이 바뀌어 다시 봐야 함 | Iris가 붙임 |

- 기존 4가지(반영됨 · 일부 반영 · 미반영 · 해당없음)에 **확인 전 · 재검토 필요** 두 가지를 더한다. 둘은 Iris만 붙이고, 사람이 확인하면 나머지 넷 중 하나로 바뀐다.

### 2-1. 반영률

```
반영률 = 반영됨 ÷ (전체 연결 − 해당없음)
```

- 일부 반영 · 확인 전 · 재검토 필요는 **반영되지 않은 것**으로 센다〔기본값〕. 보수적으로 세야 숫자를 믿을 수 있다. 대신 옆에 '일부 반영 n개'를 따로 보여 준다.
- 화면이 없는 정책(정산, 알림톡 발송 같은 서버 정책)은 반영률에서 빼고 '화면 없는 정책' 묶음으로 따로 보여 준다. 개발 확인용이다.
- ⏸ 결정 대기 정책도 반영률에 넣되, '바뀔 수 있음'을 함께 표시한다.

## 3. 변경 추적 — 새 버전을 확정할 때

새 버전과 직전 확정 버전을 **ID 기준**으로 비교한다.

| 바뀐 것 | 판단 | Iris가 하는 일 |
|---|---|---|
| 정책 추가 | 새 ID | 화면 표 '정책' 열에 있으면 그 화면에 '확인 전'으로 연결 |
| 정책 수정 | 같은 ID, 세부 규칙 문장이 다름(띄어쓰기 · 문장부호만 다르면 무시〔기본값〕) | 연결된 화면을 모두 '재검토 필요'로. 전 · 후 문장 비교 보기 |
| 정책 표기 변화 | ⏸ → ✅, 〔기본값〕 → ✅ 등 | 수정과 같게 '재검토 필요' |
| 정책 삭제 | ID가 사라짐 | 연결은 남기고 '문서에서 빠진 정책'으로 표시. 화면에서 걷어낼지 묻기 |
| 화면 추가 | 화면 표에 새 ID | 화면 칸을 새로 만들고 '디자인 없음' |
| 화면 삭제 | 화면 표에서 ID가 사라짐 | 화면 칸에 '기획서에서 빠진 화면'. 디자인은 지우지 않음 |
| 화면 행의 '정책' 열 변화 | 연결할 정책이 바뀜 | 더해진 정책은 '확인 전', 빠진 정책은 '문서에서 빠진 연결' |

- **변경 요약**을 자동으로 만든다. 바드림 기획서의 '변경 요약' 표(0-1장)와 같은 모양이고, 문서에 붙여 넣을 수 있게 복사 버튼을 둔다. 문서에 🆕 · 🔄 표시나 '대체 문장' 표를 따로 쓰지 않아도 된다.
- 디자인 쪽 바뀜(피그마 다시 불러오기)은 [13_FIGMA_LINK.md](./13_FIGMA_LINK.md) 6장 규칙으로 같은 '재검토 필요'를 붙인다.

## 4. 담당

- 화면 칸마다 **담당 디자이너 1명**을 둔다〔기본값〕. 정책은 여러 화면에 걸치므로 정책에는 담당을 두지 않는다.
- 정책 보드 · 프로젝트 홈에 '내 화면' 필터를 둔다.
- 담당이 비어 있으면 방장에게 '재검토 필요' 알림이 간다.

## 5. 알림

Phase 2에서는 **앱 안 알림**(상단 종 모양 + 목록)만 만든다. 메일 · 슬랙은 쓰임을 본 뒤에 정한다.

| 일 | 받는 사람 |
|---|---|
| 초대 요청이 왔다 | 방장 · 부방장 |
| 초대가 승인 · 거절 · 만료됐다 | 요청한 사람 |
| 내 화면에 '재검토 필요'가 붙었다 | 화면 담당 |
| 검토 요청이 왔다 | 방장 · 부방장 |
| 내 화면이 승인 · 반려됐다 | 화면 담당 |
| 문서 새 버전이 확정됐다(바뀐 정책 n개) | 연결된 화면의 담당 |
| 양식 변환이 끝났다 | 변환을 시작한 사람 |
| 코멘트에서 나를 불렀다 | 불린 사람(코멘트는 Phase 2) |

- 같은 일이 짧은 시간에 여러 번 생기면(새 버전으로 재검토 30개) 한 알림으로 묶는다.

## 6. 기록

누가 언제 무엇을 바꿨는지 남긴다. 검수의 근거가 된다.

- 남기는 것: 반영 상태 변경, 검토 요청 · 승인 · 반려, 문서 확정 · 새 버전, 양식 변환 확정, 역할 변경, 초대 승인 · 거절, 화면 칸 연결 · 해제.
- 보는 곳: 화면 인스펙터 기획 탭 아래 '기록', 정책 상세 아래 '기록', 프로젝트 설정의 멤버 기록.
- 기록은 지우거나 고칠 수 없다. 1년 보관한다〔기본값〕.

## 7. 같은 화면을 두 사람이 고칠 때

실시간 동시 편집(Phase 3) 전까지의 임시 대책이다. 지금은 나중에 저장한 쪽이 덮어쓴다([10_ERROR_STATES.md](./10_ERROR_STATES.md) 9번).

- 다른 사람이 같은 화면을 열고 있으면 화면 위에 "OO님도 이 화면을 보고 있어요"를 띄운다.
- 저장할 때 서버의 화면이 내가 연 뒤에 바뀌었으면 덮어쓰지 않고 묻는다: [내 것으로 저장] / [다른 사람 것 보기]〔기본값〕.
- 역할이 생겨 여러 명이 들어오는 시점에 함께 만든다.

## 8. 미정

- [ ] '재검토 필요' 색(보라)을 디자인 시스템 색 중 무엇으로 할지.
- [ ] 승인 조건을 이대로 할지(남은 확인이 있으면 사유 메모 필수).
- [ ] 알림을 메일 · 슬랙으로도 보낼지.
