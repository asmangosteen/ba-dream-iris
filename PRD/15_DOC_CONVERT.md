# 문서 검사 · 양식 변환

> 2026-11-26 작성. [11_PLANNING_DOC_FORMAT.md](./11_PLANNING_DOC_FORMAT.md) 6장 '문서를 올리는 두 길'의 자세한 규칙이다.
> 목표: **양식대로 쓴 문서는 바로 쓰고, 자유롭게 쓴 문서는 Iris가 양식으로 바꿔 준다. 바꿀 때 기획 내용은 절대 바꾸지 않는다.**
> 〔기본값〕은 기획 권장안이다. 답이 없으면 이대로 만든다.

## 1. 흐름

```
문서 올림(작성 · 업로드 · 링크)
  → 양식 검사(AI 아님, 바로)
      ├─ 통과 ────────────────→ 정책 · 화면 칸 · 연결 등록
      ├─ 경고만 있음 ──────────→ 등록 + 경고 목록
      └─ 필수가 빠짐 → "Iris 양식으로 바꿀까요?"
                         → AI 변환(뒤에서, 장 단위)
                         → 비교 화면에서 사람이 확인 · 고침
                         → 확정 → 새 버전으로 등록
```

## 2. 양식 검사

AI를 쓰지 않는 규칙 검사다. 문서를 올리거나 저장할 때마다 바로 돈다.

| 검사 | 결과 | 문구 예시 |
|---|---|---|
| 문서 정보 표가 없음 | 필수 빠짐 | 문서 정보 표가 없어요 |
| 정책 표(`ID` 열 + `P-영역-숫자`)가 없음 | 필수 빠짐 | 정책 표를 찾지 못했어요 |
| 화면 표가 없음 | 경고 | 화면 목록이 없어요. 화면 칸 없이 등록해요 |
| 정책 ID 중복 | 경고 | P-ORD-05가 두 번 나와요 |
| 화면 표 '정책' 열이 없는 정책을 가리킴 | 경고 | C-12가 가리키는 P-ORD-99가 문서에 없어요 |
| 화면 행의 '정책' 열이 비어 있고 문장 속 `(P-…)`도 없음 | 경고 | C-07에 연결할 정책이 없어요 |
| 옛 약자(`M-` · `MA-` · `MN-`) 사용 | 경고 | 옛 약자 M을 C로 읽었어요(프로젝트 설정) |
| 표기 규칙 표에 영역 약자 뜻이 없음 | 경고 | 영역 약자 PRD의 뜻이 없어요 |

- 경고는 등록을 막지 않는다. 문서 상세 위에 모아 보여 주고, 누르면 해당 위치로 간다.
- Iris 안에서 쓰는 문서는 쓰는 동안 같은 검사를 줄 옆에 바로 보여 준다.

## 3. AI 변환

### 3-1. AI가 하는 일

- 정책 문장을 찾아 **정책 표**로 옮기고, ID가 없으면 `P-영역-연번`을 새로 붙인다. 영역 약자는 장 제목에서 제안한다(예: '주문 · 결제' → `ORD`).
- 문서에 화면 이야기가 있으면 **화면 표**를 만들고, 화면 ↔ 정책 연결을 추정해 '정책' 열을 채운다.
- 옛 약자를 새 약자로 바꾼다(`M-05` → `C-05`). 본문 속 참조도 함께 바꾼다.
- 문서 정보 표를 채운다(제목 · 버전 · 상태는 원본에서, 모르면 빈칸).

### 3-2. AI가 하지 않는 일 — 지킬 규칙

- **정책 문장을 바꾸지 않는다.** 요약 · 다듬기 · 합치기 · 나누기 없이 원문 그대로 옮긴다.
- 새 정책을 만들거나 빠진 내용을 채우지 않는다.
- ✅ · 〔기본값〕 · ⏸ · 📌 · ⚖️ 표기를 붙이거나 떼지 않는다.
- 자유 서술 장(배경 · 플로우 · 결정 로그 등)은 손대지 않고 그대로 둔다.

### 3-3. 〔AI 추정〕 표시

- AI가 새로 붙인 ID, 추정한 화면 ↔ 정책 연결, 제안한 영역 약자에는 〔AI 추정〕을 붙인다.
- 확정하면 표시는 지우고, 기록([14_REVIEW_FLOW.md](./14_REVIEW_FLOW.md) 6장)에 'AI 변환'으로 남긴다. 이렇게 생긴 정책은 `origin: ai`다.

## 4. 비교 화면

- 왼쪽 원본, 오른쪽 변환본. 장 단위로 맞춰 스크롤한다.
- 〔AI 추정〕 항목은 강조하고, 하나씩 [받기] · [고치기] · [빼기]를 고른다. [모두 받기]도 둔다.
- 오른쪽은 바로 고칠 수 있다. 고친 곳은 표시가 '사람 확인'으로 바뀐다.
- 새 버전을 올릴 때의 버전 비교(14장 3장)도 같은 화면을 쓴다.

## 5. 저장

- 원본은 그대로 첨부해 둔다. 변환본은 그 문서의 **새 버전**으로 저장한다.
- 변환본 상태는 '초안'이다. 문서 확정은 14장 1-1 규칙을 따른다.

## 6. 길이 · 비용 · 시간

- 바드림 기획서는 길다. 바드림 몰 상세 기획서 v1.0은 약 16만 자(1,156줄), 단기구독 기획안 v6.0은 3,477줄이다. 한 번에 넣지 않고 **장(## 제목) 단위로 나눠** 바꾼다.
- 정책 ID와 화면 ID는 장을 넘어 이어져야 하므로, 먼저 전체 제목과 ID만 훑어 목록을 만든 뒤 장마다 바꾼다.
- 변환은 뒤에서 돌리고, 끝나면 알림으로 알린다. 그동안 문서는 원본 그대로 쓸 수 있다.
- AI 호출은 서버에서만 하고, 키는 서버 전용 값에 둔다([04_PROJECT_SPEC.md](./04_PROJECT_SPEC.md)).
- 프로젝트당 한 달 변환 횟수에 상한을 둔다〔기본값: 30회〕.

## 7. 권한

- 변환 실행 · 비교 화면 확정은 문서를 쓸 수 있는 사람(방장 · 부방장 · 기획 편집)만 한다([12_ROLES_PERMISSIONS.md](./12_ROLES_PERMISSIONS.md)).
