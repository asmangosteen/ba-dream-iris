# 피그마 화면 연동 규칙

> 2026-11-26 작성. [11_PLANNING_DOC_FORMAT.md](./11_PLANNING_DOC_FORMAT.md)의 화면 ID와 피그마 프레임을 잇는 규칙이다.
> 목표: **피그마 프레임을 붙이면 기획서의 화면 칸에 저절로 들어가고, 그 화면의 정책이 따라온다. 디자인이 바뀌면 검수를 다시 하게 만든다.**
> 〔기본값〕은 기획 권장안이다. 답이 없으면 이대로 만든다.

## 1. 화면 칸과 프레임

- **화면 칸** = 기획서 화면 표의 한 행(`C-05 상품 상세`). 기획서를 올리면 생긴다.
- 피그마 프레임과 자체 캔버스 화면은 화면 칸에 붙는 **디자인**이다. 화면 칸 하나에 기본 디자인 하나 + 상태 변형 여러 개가 붙는다.
- 화면 칸 없이 프레임만 있어도 된다(기획서 없는 프로젝트, 탐색 시안). 이때는 지금처럼 정책을 직접 연결한다.

## 2. 프레임 이름 규칙

| 형태 | 예시 | 뜻 |
|---|---|---|
| `ID 화면 이름` | `C-05 상품 상세` | 기본 디자인 |
| `ID/상태` | `C-05/일시품절`, `C-05/오류` | 상태 변형. 상태 이름은 화면 표 '상태' 열과 같게 쓴다 |
| `문서약자 ID 화면 이름` | `몰 C-05 상품 상세` | 한 프로젝트에 기획서가 둘 이상이고 ID가 겹칠 때 |

- 이름 **맨 앞**의 종류 약자(C · A · S · CMP) + 숫자를 ID로 읽는다. 구분은 공백 · `_` · `-` 모두 받는다(`C-05_상품상세`, `C05 상품 상세`)〔기본값〕.
- 옛 약자(`M-05`)는 프로젝트 설정의 약자 대응(11장 3-3)으로 읽는다.
- 이름에 ID가 없으면 '연결 안 된 화면'으로 두고, 인스펙터에서 화면 칸을 직접 고르게 한다.
- 같은 ID 프레임이 둘 이상이면(시안 A · B) 둘 다 붙이고 하나를 **대표**로 고른다. 반영 상태는 대표 기준이다〔기본값〕.

## 3. 가져오는 방법

1. **프레임 링크 하나**: 지금 방식 그대로.
2. **페이지 · 섹션 링크**〔기본값〕: 안의 최상위 프레임을 모두 보여 주고, 한 번에 고른다.

가져오기 창의 미리보기 표:

| 프레임 이름 | 붙을 화면 칸 | 결과 |
|---|---|---|
| `C-05 상품 상세` | 몰 C-05 상품 상세 | 새로 붙음 |
| `C-05/일시품절` | 몰 C-05 · 일시품절 | 상태 변형으로 붙음 |
| `C-12 배송지 확인` | 몰 C-12 | 이미 붙어 있음 → 다시 불러오기 |
| `C-40 이벤트` | — | 기획서에 없는 ID (경고) |
| `Frame 128` | — | ID 없음 (연결 안 된 화면) |

- ID가 맞는 프레임은 미리 체크해 둔다. 나머지는 사람이 고른다.
- 많이 가져올 때는 피그마 호출 한도 때문에 나눠서 받고 진행률을 보여 준다.

### 3-1. 정한 것 (2026-11-28, 시안 https://claude.ai/artifact/6teGBmQcTi47jgB46toMrk)

- **가져오는 방식 기본값은 '그림만(Thumbnail)'** — 페이지 · 섹션 · 프레임 모두. '편집 가능한 레이어'는 사람이 고를 때만(느리고 피그마 호출을 더 씀).
- **이미 연결된 프레임은 체크하지 않은 채로 보여 준다.** 최신으로 받고 싶을 때만 직접 체크하거나 화면의 '다시 불러오기'로.
- **링크 종류 판별**: `node-id` 가 프레임이면 프레임 하나(시안 3), 섹션 · 페이지면 미리보기 표(시안 2), 프레임 안의 요소면 "이 요소가 있는 화면 전체를 가져올까요?", `node-id` 가 없으면 파일의 첫 페이지를 미리보기 표로.
- 결과 칩 다섯 가지: 새로 붙음 · 상태 변형 · 이미 연결됨(다시 불러오기) · 기획서에 없는 ID · ID 없음(화면 칸 고르기).
- 가져오는 중에는 창을 닫아도 계속 받고, 끝나면 알림. 끝나면 빠진 디자인 · 빠진 상태 · 기획서에 없는 ID를 모아 보여 준다.

## 4. 빠진 것 찾기

화면 칸과 프레임을 맞춰 보면 누락이 저절로 보인다. 프로젝트 홈과 정책 보드에 모아 보여 준다.

| 경우 | 표시 | 뜻 |
|---|---|---|
| 화면 칸은 있는데 프레임이 없음 | 디자인 없음 | 디자인 누락 |
| 화면 표 '상태' 열의 상태 중 프레임이 없음 | 상태 디자인 없음 (예: `C-05` 오류) | 디자인 요청서에서 요청한 상태 누락 |
| 프레임 ID가 화면 표에 없음 | 기획서에 없는 화면 | 기획 누락이거나 ID 오타 |

## 5. 정책 연결

- 프레임이 화면 칸에 붙으면, 화면 표 '정책' 열의 정책이 그 화면에 **'확인 전'** 상태로 연결된다. 사람이 반영됨 · 일부 반영 · 미반영 · 해당없음으로 바꾼다([14_REVIEW_FLOW.md](./14_REVIEW_FLOW.md) 2장).
- 피그마 프레임 설명(description)에 `P-ORD-05`처럼 적은 정책도 연결 후보로 더한다〔기본값〕. 화면 표에 없는 정책이면 '기획서 밖 연결'로 표시한다.
- 상태 변형은 기본 디자인과 같은 정책 연결을 함께 쓴다. 변형마다 따로 기록하지 않는다〔기본값〕.

## 6. 다시 불러오기 · 바뀜 감지

- **기준은 피그마 노드 id**다. 프레임 이름이 바뀌어도 연결은 유지한다.
  - 이름의 ID가 바뀌면(`C-05` → `C-06`) "C-05에서 C-06으로 바뀌었어요. 화면 칸도 옮길까요?"를 묻는다.
- **언제 불러오나**
  - 수동: 화면 · 페이지 · 프로젝트 단위 '다시 불러오기' 버튼(지금 있음).
  - 자동〔기본값〕: 프로젝트를 열 때, 마지막으로 불러온 지 하루가 지난 피그마 파일만 파일 수정 시각을 확인한다. 바뀐 파일의 프레임만 다시 받는다(호출 한도 절약).
- **디자인이 바뀌면**(썸네일이나 레이어 요약이 달라지면)
  - 그 화면에서 '반영됨' · '일부 반영'이던 연결을 **'재검토 필요'**로 바꾼다.
  - 승인된 화면이면 '검토 요청'으로 되돌린다.
  - 직전 썸네일을 남겨 **바뀌기 전 · 후를 나란히** 볼 수 있게 한다(최근 5개까지)〔기본값〕.
- **피그마에서 프레임이 지워지면** '원본 없음'으로 표시한다. 마지막 썸네일과 연결은 지우지 않는다. 사람이 지우기를 고를 때만 지운다.

## 7. 컴포넌트 매칭

- 지금처럼 피그마 컴포넌트 키(`figma_component_key`)와 이름 규칙(`match_aliases`)으로 집계한다.
- 매칭에 실패한 컴포넌트 이름을 디자인 시스템 화면에 **'연결 안 된 컴포넌트'**로 모아, 관리자가 한 번 연결하면 다음부터 자동으로 잡히게 한다.

## 8. 피그마 토큰 · 호출 한도

- 토큰은 **팀 공용 피그마 계정**으로 발급한다〔기본값〕. 개인 토큰이면 그 사람이 퇴사하거나 토큰이 만료될 때 모든 프로젝트의 연결이 멈춘다.
- 토큰 만료 7일 전에 회사 관리자에게 알린다.
- 호출 한도를 넘으면(429) [10_ERROR_STATES.md](./10_ERROR_STATES.md) 규칙대로 알리고, 남은 가져오기는 잠시 뒤 이어서 한다.
- 피그마 가져오기 · 다시 불러오기는 방장 · 부방장 · 디자인 편집만 할 수 있다([12_ROLES_PERMISSIONS.md](./12_ROLES_PERMISSIONS.md)).
