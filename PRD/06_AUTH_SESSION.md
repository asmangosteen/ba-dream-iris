# 06. 로그인 유지 규칙

> 한 번 메일 인증으로 로그인하면, 쿠키가 남아 있는 동안은 다시 인증하지 않고 바로 들어옵니다.
> 사내 전용 도구라 매번 인증하는 불편이 보안 이득보다 크다고 보고, 업무용 서비스들의 기본값에 맞춥니다.

## 참고한 서비스

| 서비스 | 기본 유지 기간 | 관리자 조정 |
|---|---|---|
| Google Workspace | 웹 세션 14일 (관리 콘솔만 1시간) | 조직 단위로 기간 설정 |
| Slack | 워크스페이스 설정에 따름 | 앱을 닫을 때 로그아웃 또는 기간 지정, 끝나기 2시간 · 15분 전에 알림 |
| Iris | 마지막으로 쓴 날부터 30일 | `IDLE_DAYS` 로 조정 |

## 규칙

1. **유지 기간: 마지막으로 쓴 날부터 30일.**
   - Supabase 로그인 쿠키(`sb-*-auth-token`)는 라이브러리(@supabase/ssr)가 기한을 400일(브라우저 최대치)로 고정합니다. 접근 토큰(1시간)은 쓰는 동안 자동으로 갱신됩니다.
   - 그래서 Iris가 따로 `iris-last-seen` 쿠키에 마지막으로 쓴 시각을 남깁니다(한 시간에 한 번 갱신). 화면을 옮길 때마다 `app/middleware/auth.global.ts`가 확인해서, 30일이 넘었으면 이 기기에서 로그아웃하고 로그인 화면에 "30일 동안 쓰지 않아서 다시 로그인해 주세요"를 보여 줍니다.
   - 매일 쓰는 사람은 사실상 계속 로그인 상태이고, 30일 넘게 열지 않은 기기만 다시 메일 인증을 합니다.
2. **로그아웃**
   - `로그아웃`: 이 기기(브라우저)만 끝납니다.
   - `모든 기기에서 로그아웃`: 내 계정이 로그인된 모든 기기의 갱신 토큰을 없앱니다. 노트북을 잃어버렸거나 공용 PC에서 로그아웃을 잊었을 때 씁니다.
3. **자격이 없어지면 바로 막기**: 쿠키가 남아 있어도 매 화면 이동마다 `@ba-dream.com` 주소인지 확인하고(`app/middleware/auth.global.ts`), 데이터는 DB 보안 규칙(`is_member()`)이 멤버만 읽게 합니다. 멤버 행이 지워지면 쿠키가 있어도 데이터가 보이지 않습니다.
4. **쿠키 속성**: `SameSite=Lax`, `Secure`(https 에서만 전송). 쿠키는 브라우저 자바스크립트로 읽을 수 있어서(Supabase 클라이언트가 토큰을 갱신해야 함) 다른 사이트의 스크립트를 Iris 화면에 넣지 않습니다.
5. **공용 PC**: 쓰고 나면 꼭 `로그아웃`을 누릅니다. ("이 기기에서 로그인 유지" 선택 칸은 Phase 2에서 검토)

## 바꾸는 곳

- 기간: `app/middleware/auth.global.ts` → `IDLE_DAYS`
- 더 엄격하게(예: 일정 기간 뒤 무조건 다시 인증)는 Supabase 대시보드 Authentication → Sessions 의 "Time-box user sessions" · "Inactivity timeout" (Pro 요금제 기능)
